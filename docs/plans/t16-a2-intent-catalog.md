## 设计

用户文本经服务端意图解析后进入 Run 的可信约束；偏好中不保存购买意图。将否定、当前正向购买和被排除的候选序号一起解析，替代 memory 的二次布尔覆盖。只有明确、唯一的正向对象可以形成选中商品；冲突先澄清。Supervisor 和 Tool Guard 继续使用同一不可变约束，HITL、库存事务与幂等内核不变。

现有连接标签不足以证明具体能力。新合成目录显式声明 wired/wireless 能力，不改双模/三模标签、不推断 Bluetooth/2.4GHz。旧目录缺少能力元数据时保持保守。无线需求可匹配有明确能力的多模商品；排除标签单独保留。将确定性属性条件放入 PostgreSQL 召回 scope，在 TopK 前过滤，并在取回及准备提案时再次校验。
